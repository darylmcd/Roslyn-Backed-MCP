# ADR 0029: Explicit preview snapshot and safety authority

Status: Accepted for the next major release, 2026-10-15.

A preview must retain the exact original solution used by its producer, the actual bounded diff safety state, and its intended producer family. Convenience store paths infer an original from the native Roslyn workspace or default safety and provenance. Those assumptions can lose reviewed state and become incorrect when the manager preserves evaluated reference metadata that Roslyn omits.

Require those inputs explicitly at every store producer and interface dispatch. Remove inference and state-dropping convenience paths; migrate in-tree producers, helpers, and fakes together. Preserve generic apply routes and validate specific routes against the real producer family. A truncated preview remains refused unless the documented explicit override is used.

Isolation and recovery require an injected `IWorkspacePathPolicy`. Approve selected source directories before our explicit enumeration, then the complete frozen mutable input/destination inventory before our explicit byte reads or effects; preserve proven immutable SDK/NuGet inputs externally. Required asynchronous `PhysicalGraphLayout.CreateAsync` approves evaluated assets paths before explicit JSON reads; immutable package provenance comprises exact files from independently authorized, verified installations, with selecting-assets identities and current custom-cache grants retained. Project-evaluated paths never grant SDK or cache authority; registered tool installations and bootstrap cache boundaries establish independent provenance. Authored project inputs take precedence over containing SDK/cache roots. Configured cache ancestors alone confer no immutable ownership. Resolve nearest `global.json` candidates sequentially under current path authority before explicit metadata or byte reads. Freeze missing nearer candidates and selected configuration bytes in prepared test/stage authority; revalidate before execution/publication. If inherited configuration cannot be established before an unauthorized ancestor, refuse with guidance to place an explicit configuration inside the authorized workspace or authorize the inherited file. Migrate VSTest fixtures to explicitly owned `{}` configuration; malformed or unreadable configuration never silently selects VSTest. `TestRunPlan` requires immutable `PreparedDotnetTestContext` with exact execution-input identities and explicit `NativeTestArguments`, and `TestRunnerService` requires the injected path policy. A shared coordinate root maps enrolled inputs and never grants ownership of its parent tree. This policy is defense in depth for our explicit IO, not a native MSBuild filesystem sandbox: retain the trusted-workspace contract in [SECURITY.md](../../SECURITY.md#msbuild-evaluation) and README. Native evaluation may discover additional active authored inputs; approve their expanded input/destination manifest before our code reads or copies them. `CaptureRecoveryAsync` issues authority only after asynchronous inventory approval and exact byte capture; migrate custom managers, factories and test doubles explicitly.

`SolutionDiffReadContext` authorizes the diff/planner's explicit physical reads before byte/text access. `SnapshotOnly` accepts already materialized text and never invokes lazy text loaders. This context does not intercept earlier producer semantic operations; workspaceId-based semantic snapshot access retains the existing loaded-workspace contract.

Source persistence, preview diff/path reporting, and fork replay share one physical mutation plan. Staged graph validation reads actual evaluated files before publishing a new solution/version. Correct omitted reference metadata from independently observed trusted compiler task inputs, never from the expected preview; evaluated item defaults cannot substitute for metadata changed by executed targets. Preserve source token and undo authority when staging fails.

Issue native compiler authority only through an owned load and additional approved design-time target execution. The additional Csc execution defines the normalized compiler snapshot; do not claim to reconstruct historical metadata from the earlier load. Replay every frozen edge-selected compiler context for each loaded project, including leaves, with its exact globals, framework, tools version and target set. Require exact native parse/compilation options, source/additional/config/analyzer inputs, output and reference identities; populate only the known omitted interop bit from independently captured task inputs. Context divergence preserves the independently loaded semantic snapshot with precise unavailable compiler authority. Publish authority once, after normalized references, analyzer binding and final input checks complete. Keep command-line arguments and selected task values in bounded private memory-only IPC, drain unknown child output, and retain the trusted-MSBuild execution boundary documented in SECURITY.md.

Authorize and freeze every explicit parser dependency, including nested response files, ruleset includes and enumerated source/search paths, before our parser performs file access. Bind newly discovered compiler inputs to the normalized certificate and revalidate before publication and later mutation authority. Preserve the owned native syntax-tree options provider only after its exact analyzer-config inputs are approved and verified; do not weaken option equality to accommodate a mismatch.

Prepare analyzer isolation asynchronously from exact authorized analyzer and dependency bytes plus frozen directory membership. An unavailable context installs no product shadow reader; a newly denied dependency preserves semantic loading with unavailable mutation authority, and current grants remain required when validating the catalog.

Bind Windows shadow files and their physical directory route for the complete executable loading lifetime, preserving `Assembly.Location`. Publish fresh owned analyzer references whose metadata discovery and executable loader both consume held shadow images; preserve the original graph coordinate through the general `AnalyzerReference` contract. Never mutate a native reference that may already have an in-flight load. Retain already-loaded foreign native images only in a semantic snapshot with unavailable compiler authority. Resolve captured custom dependencies before arbitrary process-default assemblies, preserve compatible version/culture/key identity, and propagate failures to load a selected admitted image. Share only exact host contract assemblies and the independently identified host-runtime bootstrap boundary; a runtime path is not proof of immutable mapped bytes. POSIX retains the trusted native analyzer-loader boundary and does not claim the Windows shadow-image lifetime guarantee.

Shadow cleanup must preserve physical directory ownership across enumeration and deletion, including directory junctions and renamed ancestors. A path spelling beneath the cache root does not authorize traversing or deleting its redirected target.

Require `IWorkspaceManager.ReadAdmittedImagesAsync` for compiled-code analysis. Return immutable module images only for the exact admitted reference in the owned project, matching both the load-time content hash and Roslyn module identity/MVID under current input authority. Include every admitted module and its exact physical basename separately from its module-definition metadata name; never infer a linked-file alias from the metadata name or silently substitute the manifest module for another target. Image analysis inspects metadata and IL without loading executable code. Semantic loading may retain explicit unavailable image authority; a later grant requires a fresh owned load rather than certifying changed bytes retroactively. Custom managers implement the required method; native wrappers forward the authority and fixtures without admitted images refuse explicitly.

Authorize all physical linked-module paths and compare the admitted manifest with the authorized current manifest without invoking Roslyn's lazy module factory. The admitted manifest's file hashes bind linked image bytes; compare any modules already materialized by Roslyn against those same bytes, including a second observation after awaited reads. Borrow the reference's native metadata owner through the pinned non-copying API and inspect only the validated `_initialModules`, `_moduleFactoryOpt`, `_lazyData`, and nested `Data.Modules` field contracts. Retain the borrowed owner and reference across awaited checks, never mutate their caches, and never dispose them from image capture. Unknown API shapes make image authority unavailable. Qualify these private ABI dependencies against the supported package and SDK matrix before release.

A successful fork restore may replace only exact evaluated NuGet producer outputs and compiler inputs independently certified by the selected framework/RID assets entries and active package import origins. Freeze parsed assets bytes, consumed package artifacts and imports, authored/global execution inputs, and protected reviewed writes. Refresh compiler options only from an owned native candidate when certified active package build inputs change; reject direct snapshot metadata/options edits before effects. Final comparison preserves every nonpackage reference/document and reviewed output-context identity. Only successful restore commands can advance the exact generated-output epoch; failed or cancelled commands cannot mint refreshed authority.

Command plans retain captured evaluation properties through restore and test execution. Frozen evaluated dependency evidence selects native framework, reporter and filter arguments; it does not prove extension registration. The actual native host validates registration, including manual registration, and build/CLI failures use the normal typed failure envelope. Every test protocol freezes execution inputs and executes with `--no-restore`. Preparation reuses only a currently verified owned native compiler certificate and its installed-package authority; absent restore authority requires explicit restore before freezing execution inputs. Changed inputs or revoked grants refuse rather than restoring over the evidence. Native reporter and filter selection consumes that same dependency snapshot. Parse raw command results inside the owned execution boundary before sanitizing public results, logs and failure chains; preserve semantic counts, classifications and diagnostic span identity. Require executor implementations to implement safety-bearing routes explicitly rather than silently dropping early-kill or parsing state through default interface bodies.

Undo preparation must retain the preceding user undo until actual effects exist. Replace `CaptureBeforeApply` with the required `PrepareBeforeApplyAsync(physicalOperation, cancellationToken)` contract. Its `IPreparedUndoOperation` owns publication, explicit `RetainRecovery` and compensation: publish after persistence, restore that exact operation during verification, and refuse compensation after a later operation or external edit supersedes its authority. Canonical workspace recovery binds immutable byte/graph/version snapshots to the owning session independently of optional undo services, blocks further mutation in that workspace or overlapping paths, and advances version after successful explicit user recovery. An unrecovered write must retain its own recovery authority; it must never redirect recovery to an unrelated prior undo. The physical persister and prepared undo share one `IWorkspaceMutationOperation`; never independently recapture authority. A required mutation lease validates current session, mutation epoch and exact entry bytes before writes; complete it with exact post-write snapshots before publishing undo. Incomplete disposal retains uncertainty for explicit recovery; automatic compensation must own the current completed operation and validate post bytes. `IRefactoringService.ApplyRefactoringWithUndoAsync` returns the apply result and this exact handle. Migrate direct edit, project mutation, editorconfig, composite and verification callers together; do not retain capture-first or global-last-undo fallbacks.

Physical writes and inverse compensation require operating-system namespace-transition permissions in addition to data-write permission: the required delete/rename handle on Windows and source-directory rename permissions on POSIX. A writable file alone is insufficient. Refuse when these capabilities are unavailable; never fall back to an unbound pathname overwrite or check-then-delete. Current path grants remain independently required. Existing-object persistence retains the captured object's metadata and hardlink behavior; unexpected captured entries remain protected by the owning operation's recovery barrier.

Use a dedicated `.roslynmcp-custody` administrative parent outside the original and independently staged desired graph's observation footprints. Select an existing anchor only after held identities prove it shares the source filesystem, before creating the service parent or moving source bytes. Retained namespace effects must pass native graph verification before recovery ownership is released. For this next-major permission change, grant the executing account narrowly scoped rename/delete permissions in the intended workspace and creation/access permission for a disjoint custody parent on the same filesystem, or use a workspace copy with those permissions. Package restore cannot repair an operating-system permission refusal.

Recovery stages the exact current physical graph in a private approved directory, proves its complete native baseline, overlays only the owned pre-operation bytes/deletions, then loads an independent expected graph. Full mapped graph validation before publication preserves unrelated current compiler options, imports, membership and documents; do not construct an inverse from stale snapshots. Dispose native loader leases and temporary directories on success, cancellation and failures.

Multi-file text edits validate and simulate the complete ordered batch against one solution before effects, including repeated edits to the same document. Persist the final physical mutation set and staged workspace publication as one transaction, publish one undo operation, and record one change entry. This atomic text-edit contract differs from composite previews, whose documented partial writes remain recoverable. Composite snapshots, remaining-write inventory and undo dependency checks use normalized physical paths with platform-specific path identity, preserving distinct case-sensitive files.

`ITestRunnerService` requires explicit prepare, command and completion phases; remove defaults that fabricate empty context, rerun the composed method or discard version warnings. `TestRunPlan` requires an immutable `EvaluationProperties` snapshot, excluded from public serialization; restore and test execution must use that prepared context after later workspace reloads. `RestoreInvocationPlanner.ProjectRestore` requires explicit nullable `TargetFramework`, explicit nullable `AssetsPath`, and immutable per-node `EvaluationProperties`. An absent assets path represents an evaluated project without assets; it does not authorize inferring or discarding a context. Preserve framework-specific recorded roots without inventing a framework from a legacy moniker. Evaluate assets paths, active package expectations, test mode and resolved package versions with that same context; a filter safety decision must cover every selected target. A null recorded package root preserves the configured/default restore behavior.

One official MSBuild static graph evaluates project-reference edge metadata, solution configurations and active inner-build contexts. Preserve exact physical path plus escaped global-property dictionary identity, including `AdditionalProperties`, `GlobalPropertiesToRemove` and `SetTargetFramework`; never rebuild dependency contexts from paths alone. Neutralize only automatically injected `IsGraphBuild`, preserving explicit caller values and authored conditions. Resolve loaded projects by proven output identity or refuse ambiguous contexts precisely. Project/props/targets overlays evaluate reviewed bytes before source effects; command transport preserves one MSBuild escaping interpretation.

Core retains unredacted structured build diagnostic identities and original argument context in an internal parsing carrier for span enrichment. Public command results and record rendering exclude that internal state; sanitize freeform outward strings after semantic parsing and matching, preserving authored classifications and counts. Raw stdout/stderr remain inside the owned parser boundary. The required typed executor routes and required early-kill routes carry this state explicitly through every implementation.

Remove the raw `IWorkspaceManager.TryApplyChanges` entry point; migrate callers through the operation-owned physical transaction and publication contract.

The changed refusal behavior and removed in-process store entry points are breaking corrections under the release policy. Include the pending breaking fragment in the next major release; no version files change here. Migration: in-process preview producers pass their original and modified snapshots, actual computed changes and producer kind. Custom undo implementations prepare operation-owned handles and migrate verification to owned compensation; construct TestRunPlan with immutable EvaluationProperties and required PreparedDotnetTestContext (configuration candidates, native mode and execution-input identities), explicit NativeTestArguments, and ProjectRestore with explicit nullable TargetFramework, explicit nullable AssetsPath and per-node EvaluationProperties; pass the physical operation marker to PrepareBeforeApplyAsync rather than capturing a second token. Custom command executors and dotnet runners implement the required typed parsing and early-kill routes; implementations return sanitized public results without exposing raw command output. MCP clients use the paired apply route or generic apply_with_verify, and regenerate a complete preview when review output is truncated.

For omitted `autoRestore`, unreadable project evaluation or indeterminate missing-assets discovery preserves the loaded session and returns `restoreRequired=true` with a path-free `restoreFailureReason`; clients must not interpret this outcome as confirmed fresh or missing state. Explicit restore retains typed failure behavior, and cancellation propagates with the caller's token for either mode.

### Invocation-scoped fork path grants

Embedding factories must construct one `ForkInvocationPathPolicy` around their normal `IWorkspacePathPolicy` and inject that exact instance into the workspace manager, fork service, test runner, and other path-policy consumers. The host registers the wrapper once and exposes the same singleton through both concrete and interface registrations. Existing factories that pass a raw policy directly to these constructors must migrate together.

The manager issues a private fork invocation capability from the exact current original session, solution, version, destination entry, and evaluation properties. It allocates and binds the destination identity before authorizing or probing the initial entry. Initial capacity selection excludes this operation's source; insufficient capacity refuses instead of evicting the source. Current original-workspace grants authorize requested paths only within this operation. Fresh restored selecting assets and installed package bytes still issue their own compiler authority. An inherited exact-file package read receipt remains semantic-only authority for missing-assets loading.

The operation scope flows through candidate loading, internal reload, validation, and test execution. It rejects a different policy receiver, unrelated workspace identities, revoked sources, externally changed destinations, and captured continuations after disposal. Only the operation's internal publication advances the bound destination snapshot. The scope remains live through owned cleanup and is revoked last. A retained fork receives no copied grant or permanent delegated policy; later public loads and reloads use its own current grants. MCP request shapes do not change.

### Command start authority

Compiler certificates freeze ordered native item membership, import and definition roles, evaluated contexts, and condition witnesses as well as known file bytes. Re-evaluate membership through the existing trusted MSBuild boundary before reuse or queued command execution; refuse newly matching inputs before our code reads them or adopts their authority.

An owned load may retain its first native workspace only when complete admissions captured before and after that load are equal. An admitted output transition still requires one strict final load; exceptions, revoked grants, and cancellation never select another attempt.

Prepared test receipts belong to the exact issued `TestRunPlan` object. Copying a plan does not transfer its receipt. Current immutable assets skip restore; legitimately missing captured assets use an explicit restore producer before a new execution snapshot. Restore may replace only declared generated restore inputs, while authored document roles and verified package-file identities remain frozen.

`IGatedCommandExecutor.ExecuteTestAsync` requires an asynchronous start-authorization callback and a raw-execution result collector. `ExecuteAuthorizedAsync` is the distinct producer contract for test preparation and workspace auto-restore. Invoke start authorization after acquiring both command gates, immediately before the runner. Await the collector after execution while retaining those gates and the same total timeout, before redacting the public result. Preserve sanitized typed policy refusals and cancellation. Ordinary mutable build, coverage and package-list commands retain their separate raw execution contract.

This is a source-breaking in-process service-interface change for the next major release, within this ADR's existing release hold; it does not change MCP request or response shapes. Custom executors must implement `ExecuteAuthorizedAsync` and both required `ExecuteTestAsync` callbacks. Replace the old results-directory argument with `Func<CommandExecutionDto, CancellationToken, Task<TestRunResultDto>>`; pass raw execution and the linked timeout token to this collector, then redact its result. Migrate every custom executor and test double explicitly. No default interface implementation or callback omission is supported.

The service owns a fresh held results directory through execution, collection and cleanup. Collect regular TRX files through that directory's no-follow reader; printed result paths confer no read authority. Prove the directory disjoint from observed native glob/import and certified compiler-recursion traversals before creation, and preserve legitimate multiple-project/framework reports within the invocation namespace.

### Platform-specific cleanup outcomes

The operator approved conservative POSIX namespace retention on 2026-10-16. Cleanup binds to the original held directory object and removes its file contents without following replacement directories or links. It returns a required `Removed` or `Retained` outcome; failures remain exceptions. On POSIX, final directory entries and nested empty skeletons remain because descriptor ownership alone cannot bind a later name-based removal to that same object. A completed retained outcome is terminal, not a deletion failure to retry through the path. Windows captures a sharing-compatible same-object witness while the effective original list-directory pin is still held, checks live identities, and uses an object-bound disposition while retaining that witness through retries.

Staged baseline validation and desired reconstruction use distinct exclusive coordinates. Reconstruction recomputes the copy inventory, path mappings, relocated globals and native candidate from the fresh coordinate; retained baseline directories cannot affect later `Exists` conditions or globs. Stage disposal logs retained directory names separately from validation failures.

Fork cleanup closes its workspace and reclaims owned file contents. A retained POSIX skeleton produces an explicit `CleanupWarnings` entry; the fork retention result describes the executable workspace, not a promise that every directory name disappeared. Cancellation and failure cleanup preserve the primary exception and attach cleanup outcomes. No additional public DTO field is introduced. Existing expiry admission in dedicated service namespaces remains; expiry cleanup captures the current object and never performs a POSIX final-name unlink. Sweeps recognize content-free POSIX skeletons through held no-follow scopes and skip them without repeating reclamation claims, including across restart. This inspection only removes work; it confers no new cleanup authority. Directory skeletons require separately enforced exclusive ownership for final removal; age alone does not authorize a later unsafe namespace reaper. Current and floor runtime qualification remain pending.

| Platform | Ownership boundary |
|---|---|
| Windows | Exclusive native directory creation returns the effective original no-delete handle atomically, relative to the already held parent. Retain that handle throughout cleanup-witness issuance; no create-then-reopen gap. |
| POSIX | Exclusive mkdir is followed by no-follow descriptor acquisition. Verify current child identity and require descriptor-relative enumeration to be empty before issuing fresh cleanup ownership. Refuse populated replacements without deleting their entries. Ownership begins at captured empty-object admission, not an unproved mkdir-creator identity. |

After empty-object admission, subsequent contents belong to the existing service-owned namespace contract. POSIX final directory names remain retained; this does not add historical creator authentication to expiry reclamation.

## Public status across native project contexts

Public project status and semantic test classification aggregate the exact native contexts matching the loaded project and output: union their target frameworks and report test capability when any matching context provides it. When output types conflict, use the loaded Roslyn compilation's `OutputKind`. Producer-specific context resolution still requires one exact context and refuses ambiguity; status aggregation does not select a producer context.

## Embedding clock migration

The public `WorkspaceForkApplyService` constructor requires a `TimeProvider` argument immediately after the dedicated `forkParent` argument. In-process integrations must pass `TimeProvider.System` or their application-owned provider explicitly so one restore deadline covers planning, capture, producers and final authority checks.

The host supplies `TimeProvider.System`; deterministic tests supply their owned clock. This constructor migration remains part of the next-major publication hold and grants no release exception.
