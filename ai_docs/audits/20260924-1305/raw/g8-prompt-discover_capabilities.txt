Here are the server capabilities relevant to **refactoring**:

**Tools (44):**
- `rename_preview` [stable] (read-only) — Preview a rename refactoring.
- `rename_apply` [stable] (destructive) — Apply a previously previewed rename refactoring.
- `organize_usings_preview` [stable] (read-only) — Preview using-directive cleanup.
- `organize_usings_apply` [stable] (destructive) — Apply a previously previewed organize-usings operation.
- `format_document_preview` [stable] (read-only) — Preview document formatting.
- `format_document_apply` [stable] (destructive) — Apply a previously previewed document format operation.
- `format_check` [experimental] (read-only) — Report documents that would change under Roslyn's formatter without applying edits (workspace-wide format-verify).
- `code_fix_preview` [stable] (read-only) — Preview a curated diagnostic code fix.
- `code_fix_apply` [stable] (destructive) — Apply a previously previewed curated code fix.
- `restructure_preview` [experimental] (read-only) — Preview a syntax-tree pattern-based find-and-replace using __placeholder__ captures.
- `replace_string_literals_preview` [experimental] (read-only) — Preview replacing string literals in argument/initializer position with a constant expression.
- `change_signature_preview` [experimental] (read-only) — Preview adding/removing/renaming/reordering a method parameter with all callsites updated atomically.
- `parameter_object_preview` [experimental] (read-only) — Preview grouping N parameters of a method into a positional sealed record DTO with all callsites updated atomically.
- `symbol_refactor_preview` [experimental] (read-only) — Composite preview chaining rename + edit + restructure operations into a single token.
- `split_service_with_di_preview` [experimental] (read-only) — Composite preview splitting a service into partitions + forwarding facade + DI-registration deltas.
- `record_field_add_with_satellites_preview` [experimental] (read-only) — Composite preview synthesizing coordinated edits for satellite members when a type gains a new field.
- `get_code_actions` [stable] (read-only) — List Roslyn code fixes and refactorings at a location or selection range. Selection-range refactorings include introduce parameter and inline temporary variable. Pass endLine/endColumn for selection-range actions.
- `preview_code_action` [stable] (read-only) — Preview a Roslyn code action before applying it.
- `apply_code_action` [stable] (destructive) — Apply a previously previewed Roslyn code action.
- `move_type_to_file_preview` [stable] (read-only) — Preview moving a type declaration into its own file.
- `move_type_to_file_apply` [experimental] (destructive) — Apply a previewed move-type-to-file refactoring. Removes the type from the source file and creates its own dedicated file.
- `change_type_namespace_preview` [experimental] (read-only) — Preview relocating a type between namespaces in the same project. Rewrites the type's namespace declaration, optionally moves the file, and adjusts consumer using directives respecting ambient-namespace resolution.
- `extract_interface_preview` [experimental] (read-only) — Preview extracting an interface from a concrete type within the same project. Optionally replaces concrete type references with the interface.
- `extract_interface_apply` [experimental] (destructive) — Apply a previewed interface extraction. Creates the interface file, updates the type's base list, and applies usage replacements if requested.
- `bulk_replace_type_preview` [stable] (read-only) — Preview replacing all references to one type with another across the solution. Scope can be 'parameters', 'fields', or 'all'. 'parameters' also covers generic arguments in implemented-interface / base-class declarations so the class's interface contract stays in sync. Useful after extracting an interface.
- `bulk_replace_type_apply` [experimental] (destructive) — Apply a previewed bulk type replacement or invocation rewrite. Redeems tokens from bulk_replace_type_preview and replace_invocation_preview.
- `replace_invocation_preview` [experimental] (read-only) — Preview rewriting every call-site of a method to call a different method with a declared argument-reorder mapping derived from parameter-name equality. Redeem the token with bulk_replace_type_apply.
- `extract_type_preview` [stable] (read-only) — Preview extracting selected members from a type into a new type. Adds a private field and constructor parameter for composition. Use get_cohesion_metrics and find_shared_members to plan the extraction.
- `extract_type_apply` [experimental] (destructive) — Apply a previewed type extraction. Moves members to the new type file and wires composition in the source type.
- `extract_method_preview` [stable] (read-only) — Preview extracting selected statements into a new method. Uses data-flow analysis to infer parameters and return values.
- `extract_method_apply` [experimental] (destructive) — Apply a previously previewed extract method refactoring.
- `extract_shared_expression_to_helper_preview` [experimental] (read-only) — Preview extracting a shared sub-expression into a synthesized private static helper and rewriting every structurally-identical call site in the scope.
- `fix_all_preview` [experimental] (read-only) — Preview fixing ALL instances of a diagnostic across a scope.
- `fix_all_apply` [experimental] (destructive) — Apply a previously previewed fix-all operation.
- `format_range_preview` [stable] (read-only) — Preview formatting a specific range within a document.
- `format_range_apply` [experimental] (destructive) — Apply a previously previewed range format operation.
- `recommend_workflow` [experimental] (read-only) — Recommend first-hop Roslyn MCP tools for a natural-language task.
- `move_type_to_project_preview` [experimental] (read-only) — Preview moving a type declaration into another project.
- `extract_interface_cross_project_preview` [experimental] (read-only) — Preview extracting an interface from a concrete type into a different project.
- `dependency_inversion_preview` [experimental] (read-only) — Preview extracting an interface and updating constructor dependencies.
- `migrate_package_preview` [experimental] (read-only) — Preview migrating a package across affected projects.
- `split_class_preview` [experimental] (read-only) — Preview splitting a class into a new partial file.
- `extract_and_wire_interface_preview` [experimental] (read-only) — Preview extracting an interface and updating DI registrations.
- `apply_composite_preview` [experimental] (destructive) — DESTRUCTIVE — applies a previously-previewed orchestration operation to disk. The _preview suffix names the redeemed preview token; name kept for API stability. Pair with a *_preview call in the same session.

**Common Workflows:**
- **Code Action Flow**: `get_code_actions` → `preview_code_action` → `apply_code_action` → `compile_check`
- **Rename Flow**: `rename_preview` → `rename_apply` → `compile_check` → `test_related_files` → filtered `test_run`
- **Curated Fix Flow**: `diagnostic_details` → `code_fix_preview` → `code_fix_apply` → `compile_check`
- **Extract Interface**: `extract_interface_preview` → `extract_interface_apply` → `bulk_replace_type_preview` → `bulk_replace_type_apply`
- **Extract Type (SRP)**: `get_cohesion_metrics` → `find_shared_members` → `extract_type_preview` → `extract_type_apply`
- **Move Type to File**: `move_type_to_file_preview` → `move_type_to_file_apply`

**Key Patterns:**
- **Preview/Apply**: Most write operations use a two-step preview-then-apply pattern. Call the `*_preview` tool first, inspect the diff, then call the corresponding `*_apply` tool with the preview token.
- **Fast validation**: After routine code edits, call `compile_check` first. For changed-file verification use `validate_recent_git_changes` or `validate_workspace`; for tests use `test_related_files` to get a focused filter, then pass that filter to `test_run`. Reserve `build_workspace` / `build_project` for CI-parity or project-system changes.
- **Navigation**: Prefer `document_symbols` for file outlines and `find_references` for callers/usage tracing instead of scanning files manually.
- **Workspace Gate**: All tools require a `workspaceId` from `workspace_load`. The workspace serializes concurrent requests.

Use the `server_catalog` resource at `roslyn://server/catalog` for the complete machine-readable inventory.
