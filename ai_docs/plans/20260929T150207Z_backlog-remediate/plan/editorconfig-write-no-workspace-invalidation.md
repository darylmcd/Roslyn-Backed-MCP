| Diagnosis | `EditorConfigService.SetOptionAsync` writes .editorconfig without invalidating the loaded workspace; `FileWatcherService.Watch` excludes .editorconfig, so external edits also leave diagnostics stale. The writer accepts a source path outside the selected workspace and can create config there. The watcher precedence comment at :214-219 contradicts last-writer-wins implementation. The disk overlay in `GetOptionsAsync` remains necessary for Warn/Off policies and direct reads. |
| Approach | Resolve sourceFilePath to a loaded document and derive the physical config path; reject source/config paths outside the workspace. Watch configs recursively inside the workspace and nonrecursively at applicable ancestors. Use an internal coordinator with one locked read/write file handle for baseline comparison, parsing, pre-image capture, and write. Fail on drift or path replacement; recheck held-inode bytes before write and use a Linux advisory lock. Keep ExternalEdit for divergent bytes and Apply for committed owned bytes. Restore pre-image bytes after failed writes while the handle is held; if restoration fails and server bytes remain, record a recoverable undo/change for that mutation. Let watcher comparison reads share delete. Commit undo and change tracking only after success. Eagerly close editorconfig parse reads before yielding. For undo and other atomic writes, hold a unique temp handle through commit, detect replaced paths, retry bounded Windows destination-reader conflicts, and report failed cleanup through callers. Keep GetOptionsAsync disk overlay and published constructor/IFileWatcherService signatures; alternate managers without coordination fail closed. |
