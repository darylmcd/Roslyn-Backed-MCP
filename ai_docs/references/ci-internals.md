## Shard planner

| Fact | Detail |
|---|---|
| Plan source | `eng/get-test-shard-plan.ps1` reads compiled MSTest metadata; exact `ClassName=` predicates |
| Fail-closed | Invalid index/count, missing assembly, unreadable metadata, unsafe class name, zero classes, empty shard, overlap, incomplete assignment |
| Weighting | Hosted legs: duration profile (below). Local and unsharded runs: static case weight |
| Assignment | Greedy: classes sorted by balance weight descending (ties by ordinal class name), each placed on the lowest-score shard (cumulative weight; with Linux build times, `log(weight + class weight)` plus a build-time offset); every shard must end non-empty |
| Windows partition | Fixed by `eng/shard-duration-profile.json` |
| Linux partition | Profile weights scaled per run by the calibration builds (next section) |
| Docs route | No plan: the leg uses `eng/docs-tier-test-consumers.json` |

## Linux runner capacity (calibration)

1. Each sharded Linux matrix leg (`test_shard_count > 1`) times the same checked Release build with the release verifier's build-server settings. The docs-route leg is unsharded and skips this.
2. `eng/resolve-linux-shard-build-times.ps1` reads each sibling's build-step duration from the run's Jobs API (read-only, run-scoped) and orders them by shard index.
3. The planner gives faster runners more work using each shard's build duration as a relative speed multiplier.
4. Every leg needs the complete vector and logs the partition hash. A partial rerun uses the earliest successful build duration per index from the same run, preserving the partition other jobs already used.
5. Failure mode: the resolver polls until every sibling build completes and throws after 3 minutes (the step cap is 4 minutes). One late or failed sibling fails every Linux leg; rerunning the failed jobs recovers. Row: `ci-linux-calibration-sibling-wait-coupling` (it records the decision here when made).

## Duration-profile refresh

`eng/shard-duration-profile.json` is generated by `eng/collect-hosted-shard-timings.ps1 -ProfileJson`.

| Rule | Detail |
|---|---|
| Inputs | Five complete green first-attempt PR code runs, one TRX artifact per matrix leg, same run IDs on both images. Never a local measurement, red or cancelled run |
| Verify first | Each run's conclusion, attempt number, head and every leg through GitHub; the offline generator cannot verify remote status |
| Class inclusion | Static case weight unchanged and positive measured duration in every sampled run |
| Output | Write JSON to a scratchpad path, inspect run IDs and class counts, then replace the committed profile |
| Artifact retention | Per-leg TRX expires after 14 days; refresh only from in-window runs |
| Hand edits | Never. Close a gap by a fresh refresh |

Checklist:

1. Confirm five qualifying runs exist (`gh run view` per run; every leg present).
2. Download artifacts; build the `-LegManifest` and `-ResultsRoot` inputs.
3. Run the collector with `-ProfileJson`; read its skew table.
4. Compare against the previous profile and the decision-log baseline.
5. Replace the committed profile; run `TestShardPlanContractTests` and related planner tests.
6. After merge, measure five new complete green runs and compare critical path and achievable gain against the decision-log baseline before closing `ci-shard-duration-profile-hosted`.

Runtime semantics (hosted `verify-release.ps1` selects the profile by matrix runner image):

| Case | Behavior |
|---|---|
| Class in profile with unchanged static case weight | Uses its mean case seconds |
| Class absent, or static case weight changed | Static weight times the image's mean seconds per static case (fallback) |
| Missing image, malformed profile, fewer than `MinimumSamples` (5) source runs, no matching current classes | Fails closed |

Fallback classes mis-weight a leg until five sampled runs carry the class unchanged. The current fallback list and its measured error are time-bound: see row `ci-windows-six-shard-rebalance-remeasure`, not this file.

Re-check trigger: re-run the collector when the shard count changes, when non-test work moves between legs, or when a hosted image's achievable gain exceeds its single-leg noise band across at least five complete green runs. Never calibrate from a single sample or feed a local Windows profile into the `windows-latest` profile.

## Release verifier behavior (`eng/verify-release.ps1`)

- Calls `eng/prepare-validation-dependencies.ps1`: checked main restore plus canonical all-sample preparation (which composes `eng/prepare-test-fixtures.ps1`, the sole sample-discovery owner, also used by direct tests and `just test`).
- Verifies restored root-solution licenses on non-test-only legs (root-solution and active package-root filters; sample assets do not replace root metadata).
- Builds Release; runs tests in a private per-invocation `TEMP`/`TMP`/`TMPDIR` with reusable MSBuild and compiler servers disabled; removes that temp root; publishes the stdio host; writes the hash manifest.
- Preparation or license failure prevents build, tests and publication. Test and cleanup failures are aggregated, not hidden.
- CI passes `-TestShardOnly` on non-owner legs so platform-neutral policy and publish/hash work runs once, on the artifact owner. `-DocsTierConsumerTests` keeps every step and replaces only the test filter.

## Quality job

30-minute cap, full-history checkout, latest `10.0.x` SDK. Order: mandatory audit (restores its own solution assets); on an exact cache miss, canonical sample preparation and explicit package save; on code PRs and merge groups, a checked Debug build of `analyzers/ServerSurfaceCatalogAnalyzer/ServerSurfaceCatalogAnalyzer.csproj` (restore alone does not produce the project analyzer binary), then the changed-file formatter with `-NoRestore`. Dispatch/schedule keep the audit and conditional sample preparation/cache save. Docs and evidence routes skip the job.

## NuGet cache lifecycle

| Site | Writer | Notes |
|---|---|---|
| Linux code PRs, merge groups, dispatch, schedule | `quality` job, after strict audited main restore plus sample preparation, before analyzer/formatter work | |
| Windows code PRs and merge groups | Shard index 0 | Saves before either release step |
| Policy-doc Linux | The artifact owner (sole leg) | Same preparation as release verification |
| Evidence and SDK-floor routes | None | Uncached |

Invariants:

- Restore-only and save-only actions are pinned; no matrix reader registers post-test cache compression.
- Restore and save share `NUGET_CACHE_PATH`, the OS-qualified dependency hash key and fallback prefix. Save uses the restore action's primary-key output, never a recomputed key.
- Save only after successful population when `cache-hit != 'true'`; exact hits and readers never save. Prefix hits and cold misses keep population and persistence.
- Every release leg performs checked preparation even on a cache hit. Cache state never substitutes for restore, audit, build, tests or release gates.
- Caches are immutable per key; readers may restore before the writer saves. Lookup is OS/version and current/default/applicable-base-ref scoped; PR-created caches stay PR-ref scoped and are not promoted to `main`. Dispatch/schedule on `main` can populate the default-branch Linux cache.
- Save work consumes its writer's unchanged job budget. A warm hit proves no cold save: inspect key, matched key, ref, OS, explicit save and cleanup logs. Linux observations do not prove Windows persistence. Claim a steady-state improvement only after a fresh five-complete-green-run timing calibration.
- Cache keys hash `Directory.Packages.props`, `Directory.Build.props` and `global.json`.

## Linux PowerShell startup cache

- Linux `validate` legs and the NuGet `publish` job run `eng/initialize-pwsh-startup-cache.sh` before their first PowerShell step. One normal seed records a fresh job-private `StartupProfileData-NonInteractive`, then the file is set read-only (mode 444); the private cache directory stays writable (mode 700) for module analysis, telemetry and siblings.
- The helper persists the unique `RUNNER_TEMP` cache root through `GITHUB_ENV` (as `XDG_CACHE_HOME`); unchanged test launchers inherit it. Normal JIT and every functional test stay enabled. Runner teardown owns cleanup.
- Post-seed optional startup recording is intentionally denied. This boundary does not establish the cause or cure of any prior native crash.
- Routing, quality, evidence, aggregate and SDK-floor jobs keep their existing lifetime. Local operator runs are outside this boundary.

## Test-result summaries

`eng/summarize-test-results.ps1` must stay path-safe: job summaries carry bounded class/method names and timings, never TRX `codeBase` or source-path metadata.

## NuGet vulnerability audit

CI and `just vuln-audit` run `eng/verify-nuget-audit.ps1`: forces restore with `NuGetAuditMode=all` and promotes NU1900-NU1904 to errors, covering advisory-source failure plus vulnerable direct and transitive packages.
