**Fixed:** `get_source_text` (and other tools) called with a nonexistent file path concurrent with an auto-reload now returns `category=NotFound` (the true cause) instead of the misleading implementation-detail `category=WorkspaceReloadedDuringCall`. The gate retries after the reload and, when the second attempt also fails with "Document not found", stamps `ReloadConfirmedNotFound=true` in `_meta`; `ToolErrorHandler` uses this flag to route to the correct category. Symbol-resolution failures (where the handle targets the pre-reload compilation) are unaffected and continue to surface `WorkspaceReloadedDuringCall` as intended. Closes gh #628.
