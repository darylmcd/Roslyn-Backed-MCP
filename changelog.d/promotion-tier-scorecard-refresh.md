The canonical promotion scorecard (`audit-reports/_latest-promotion-scorecard.json`) is now tracked in git — `.gitignore` ignores `audit-reports/*` with a single negation instead of the whole directory — so the release-gating input read by `eng/aggregate-promotion-scorecards.ps1` has history, and a lost refresh is visible as an absent diff instead of failing silently. The shipped `mcp-server-surface-test` prompt now states that both run artifacts are written to the audited repo's PRIMARY checkout (never the disposable Phase-6 worktree), requires copy-back before worktree teardown, and exempts those two canonical paths from the run-end clean gate. This is the root cause of the 2026-05-31 loss, where a scorecard computed against server 2.3.1 never reached the canonical location and left no history to recover from. Does not refresh the snapshot itself — that requires an out-of-band `/mcp-server-surface-test --full` run; `promotion-tier-execution-batch` stays open.
