- **Fixed:** `extract_interface_preview` no longer no-ops on every implemented interface of the requested name: it no-ops only when that interface (with its base interfaces) is implemented by every requested member, otherwise it generates the interface beside it, keeps the original implemented, and refuses only a real target conflict (a same-named type already in the target namespace); every reference the new interface would capture (the original's, an unrelated same-named type's, a downstream project's, each linked copy of a file, including the source type's own and the files `replaceUsages` retypes) is re-pinned to what it bound to, linked copies that differ in text or would pin a name to different types refuse the preview, and a capture inside a source-generated document refuses the preview. `extract_interface_cross_project_preview` and `dependency_inversion_preview` share the re-pin; `extract_and_wire_interface_preview` is unchanged and still refuses a type that implements an interface of that name. Migration: a caller that relied on the zero-change warning for a same-named interface lacking requested members now gets a generated interface (pick another `interfaceName` or restrict `memberNames` to keep the no-op), and a same-namespace one lacking them is refused as a conflict. Closes `extract-interface-same-name-unrelated-contract-noop`.
