- **Fixed:** `extract_interface_preview` no longer returns a zero-change "already implements" no-op for every implemented interface of the requested name: it no-ops only when that interface (with its base interfaces) is implemented by every requested member, and otherwise generates the requested interface beside it, keeping the original implemented and refusing only a real target conflict (a same-named type already in the target namespace, "already exists in project …"); every reference the new same-namespace interface would capture (the original's, an unrelated same-named type's, and a downstream project's that would gain an ambiguity) is re-pinned to what it bound to before, a failure after such a re-pin names a remedy that does not blame `replaceUsages`, and a captured reference in a source-generated document refuses the preview ("would rebind … source-generated document") because no preview can edit it; a generic `IFoo<T>` is a different type and neither counts as coverage nor is rewritten. `extract_interface_cross_project_preview` and `dependency_inversion_preview` use the same re-pin, so a same-named interface visible at the source type no longer makes them drop the original from the base list or fail with an ambiguity; `extract_and_wire_interface_preview` is unchanged and still refuses a type that implements an interface of the same name. Migration: callers that relied on the zero-change warning for a same-named interface that lacks some requested members now receive a generated interface (pick another `interfaceName` or restrict `memberNames` to keep the old no-op), and a same-namespace interface that lacks them is refused as a target conflict. Closes `extract-interface-same-name-unrelated-contract-noop`.
