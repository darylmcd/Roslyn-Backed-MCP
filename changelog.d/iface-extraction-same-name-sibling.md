- **Fixed:** `extract_interface_preview` no longer no-ops on every implemented interface of the requested name: it no-ops only when that interface (with its base interfaces) is implemented by every requested member, otherwise it generates the interface beside it, keeps the original implemented, and refuses only a real target conflict (a same-named type already in the target namespace). A reference to a type named like the interface that the new interface would capture (the original's, an unrelated same-named type's, one reached through a using alias, a downstream project's, each linked copy of a file) is re-pinned to what it bound to; a capture that cannot be re-pinned (a generic or nested alias target, a namespace alias, a reference in a source-generated document, linked copies that differ in text or would pin a name to different types, a linked copy that no longer compiles) refuses the preview with the cause and a remedy that fits the route. A file linked into several projects is edited once and propagated to every copy only when the route edited a single copy; `extract_interface_cross_project_preview` and `dependency_inversion_preview` share the re-pin and no longer add a project reference for a linked file the re-pin edited identically in every copy; `extract_and_wire_interface_preview` is unchanged and still refuses a type that implements an interface of that name. Migration: a caller that relied on the zero-change warning for a same-named interface lacking requested members now gets a generated interface (pick another `interfaceName` or restrict `memberNames` to keep the no-op), and a same-namespace one lacking them is refused as a conflict. Closes `extract-interface-same-name-unrelated-contract-noop`.
