category: Fixed

- **Fixed:** `workspace_load` no longer exhausts Linux inotify instances. Every `FileSystemWatcher` owns one inotify instance and the default per-user cap is 128, but each loaded workspace used about 9 watchers plus one per ancestor directory (roughly 12 to 18 instances), so the default `MaxConcurrentWorkspaces` of 16 could not be held and loads failed with "The configured user limit (128) on the number of inotify instances has been reached". A workspace now uses one recursive tree watcher (which also detects deletion or rename of the loaded solution or project file), and the non-recursive ancestor-directory watchers that serve `.editorconfig` changes and root-directory removal are shared and reference counted across workspaces, so each additional workspace under the same parent costs one instance. A failed watcher start now releases everything it had acquired and, on Linux, names `fs.inotify.max_user_instances` in the error. Replacing the loaded solution or project file by renaming another file over it (an atomic save) no longer counts as the file being removed, and watched file extensions are now matched case-insensitively on Linux as they already were on Windows. Found when the v5.1.0 `publish-nuget` run exhausted the limit while running the full suite in one process.
