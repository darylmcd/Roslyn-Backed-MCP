- **Changed — BREAKING:** The flat location members of `PropertyWriteDto` (`find_property_writes`) and `MutationCallerDto` (`find_type_mutations` external callers) are removed; `location` is the only representation and is always present (`locationdto-secondary-dto-flat-field-lifecycle`). Removed: `filePath`, `startLine`, `startColumn`, `endLine`, `endColumn`, `containingMember`, `previewText` on property writes, and `filePath`, `startLine`, `startColumn`, `containingMember`, `previewText` on mutation callers. `writeKind` and `callerPhase` stay top-level and equal `location.classification`. A reference whose span has no file path now takes the owning document's file path (or its name) instead of an empty `filePath`. These DTOs never had a deprecation window: this is an operator exemption from `docs/release-policy.md` dated 2026-10-28, because both already carried a complete `location` since 4.x stage 2 and the primary DTOs lost their flat members in the same release. Migration: read `location.filePath`, `location.startLine`, `location.startColumn`, `location.endLine`, `location.endColumn`, `location.containingMember` and `location.previewText` instead of the removed flat members.
