- **Added:** `workspace_load` invokes MCP `elicitation/create` (2025-06-18) when called without a `path` argument and the client declares the `elicitation` capability. The middleware filter (`StructuredCallToolFilter`) intercepts the `InvalidArgument: missing 'path'` error, asks the user for an absolute path via `IMcpServer.ElicitAsync`, and re-dispatches the tool with the elicited value patched into the arguments dictionary. Sensitive-argument elicitation (credentials, tokens, secrets, passwords, API keys, auth headers) is explicitly forbidden — only `(workspace_load, path)` is on the strict allowlist, and a defense-in-depth `IsSensitiveFieldName` predicate refuses any sensitive name even if a future careless allowlist addition let one through. Per MCP spec § Elicitation security: "Servers MUST NOT request sensitive information." Clients without elicitation support, or users who decline / cancel, continue to receive the existing `schemaHint`-augmented `InvalidArgument` envelope unchanged. The capability-check helper (`StructuredCallToolFilter.HasElicitation`) is public so the upcoming `elicit-disambiguation-on-multi-symbol-resolve` initiative can reuse it. Closes `elicit-workspace-path-on-missing-required-arg`.
