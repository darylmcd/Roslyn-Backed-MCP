category: Changed
---
- **Changed:** `DiagnosticDto.filePath` is kept and is no longer `[Obsolete]`; it is now populated by every diagnostic producer whenever a file is known (`diagnostic-file-only-location-representation`). It names the file the diagnostic is about, so a file-only diagnostic (`NU1201` against a project file, `MSB1009`, unresolved-analyzer and `WORKSPACE001` project diagnostics) reports `filePath` with `location: null`, and a positioned diagnostic carries both with `location.filePath` equal to `filePath`. `location` still exists only when a path and a start position exist. Snippet and script diagnostics report `<snippet>` / `<script>`. The other flat members of `DiagnosticDto` (`startLine`, `startColumn`, `endLine`, `endColumn`) and the flat members of `SymbolDto` and `TypeUsageDto` stay removed. C# consumers: the positional constructor gained a required `FilePath` argument before `Location`. Migration: 4.4.0 marked `DiagnosticDto.FilePath` obsolete and told you to use `Location`; stop treating it as deprecated and read `filePath` for the file of any diagnostic, `location` for the span.
