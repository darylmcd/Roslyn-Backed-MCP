- **Fixed:** Failed document-set persistence now compensates only paths it provably left in a recorded post-state (including `.csproj` rewrites by `TryApplyChanges`). A path edited, replaced or recreated outside the operation is preserved and reported as an ownership-conflict `IOException` aggregated with the primary and independent cleanup failures; captured-but-untouched files are never restored or deleted. Every captured path is re-verified against its last recorded state before each effect group (`TryApplyChanges`, SDK-project restore, trivia-drift restore, project-file mutations); a path found changed is marked foreign and never adopted afterwards. A path whose post-write read-back fails keeps only its intended post-state, so an unreadable partial file is preserved and reported as a conflict instead of restored. Ownership is best-effort: the compare-then-act window between the check and the restore/delete remains. Closes `physical-compensation-external-edit-ownership`.
