- **Fixed:** narrowed a validation-to-use link-swap (TOCTOU) race in `apply_text_edit` — `ClientRootPathValidator.ValidatePathAgainstRootsAsync` now returns the boundary-canonicalized target it approved, and the edit-service write path persists to that pinned location instead of re-walking the client-supplied path (which could be redirected outside the configured sanctioned-root boundary by a symlink/junction swap between validation and write). The pin is honored only when it denotes the same physical file the edit service resolves the document to; a request whose lexical and physical resolution disagree (a `..` segment following a link, where `Path.GetFullPath` collapses `..` but the boundary's physical walk deliberately does not) is **refused** rather than pinned, because writing to the physically-resolved target there would put the edited document's text into a different file with the undo snapshot pointing at the original. Added deterministic regressions for the link-swap, the divergent-resolution refusal, and the tool-layer forwarding. Two related exposures remain tracked follow-ups: the preview/apply-token write tools (`apply_multi_file_edit` plus the `ToolDispatch.ApplyByTokenAsync`-routed tools), and `MSBuildWorkspace.TryApplyChanges`, which flushes changed documents to disk itself using the un-canonicalized `Document.FilePath`.
