- **Changed — BREAKING:** Server-side sanctioned-root failures now report `InvalidOperation` instead of `InvalidArgument`: a configured sanctioned root that cannot be canonicalized (message "A configured sanctioned root could not be canonicalized. Check ROSLYNMCP_SANCTIONED_ROOTS on the server.", `exceptionType` `InvalidOperationException`) and a failed client-roots request (message "Path validation failed because the client roots narrowing boundary could not be obtained."). Caller boundary denials keep `InvalidArgument`, the opaque "outside the configured sanctioned-root boundary" message and the exact `ArgumentException` type; an unusable request narrowing root is an `InvalidArgument` attributed to `narrowingRootPaths`. No envelope echoes a path. Migration: treat `InvalidOperation` from path-taking tools as an operator/server configuration or client-transport fault (fix `ROSLYNMCP_SANCTIONED_ROOTS` or the client's roots support) instead of correcting the caller's path argument.
