- **Fixed:** `change_type_namespace_preview` matches namespaces by identity instead of by the spelling of an import. An escaped (`using @Old.Sub;`) or interior-trivia (`using Old . Sub ;`) import of the emptied old namespace is removed, an existing destination import in another spelling is no longer duplicated, `fromNamespace` such as `Source.class` finds a type declared in `namespace Source.@class`, and the synthesized consumer import escapes keyword segments (`using Target.@class;`). Behaviour changes: an alias import (`using A = Old;`) is no longer treated as an import of the old or the new namespace, so it is left untouched (an alias of the emptied old namespace, `using A = Old;`, therefore stays and may then dangle) and a plain `using New;` is added even when only `using N = New;` exists; a leading `global::` qualifier does not change which namespace an import names; a source and destination that name the same namespace (`Old` and `Old` or `@Old`) are refused with an argument error naming `toNamespace` instead of an `InvalidOperationException`, so callers that caught the previous exception type for this refusal must catch the argument error. Closes `relocation-using-semantic-identity`.
