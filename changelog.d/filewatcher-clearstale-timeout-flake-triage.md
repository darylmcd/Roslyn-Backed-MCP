- **Maintenance:** Replaced the wall-clock timeout bound in `FileWatcherClearStaleAwaiterTests.ClearStale_ReleasesAwaiterParkedOnPriorSignal_RatherThanStrandingIt` with a deterministic synchronous state check, resolving a registered CI flake. The test parked on `WaitForStaleAsync` with a cancelable token — which returns a `Task.WaitAsync` wrapper resolved via a thread-pool continuation — then bounded pass/fail on a 10,000 ms `await`, so self-hosted-runner scheduling load produced spurious `TimeoutException` reds on unrelated diffs (PRs #1034, #1085, #1086). It now parks with `CancellationToken.None` (the raw signal task) and asserts `IsCompleted`/`IsCanceled` the instant `ClearStale` returns, since `TrySetCanceled` transitions TCS state synchronously on the calling thread and `RunContinuationsAsynchronously` defers only continuation *scheduling*. A non-gating bounded hang-guard await remains. Regression value re-verified by temporarily reverting `ClearStale`'s `TrySetCanceled` — the test fails in 34 ms instead of waiting out a 10 s timeout. `FileWatcherService` is unchanged (it was already correct); the resolved entry is deleted from `ai_docs/known-flakes.md`. Closes `filewatcher-clearstale-timeout-flake-triage`.
