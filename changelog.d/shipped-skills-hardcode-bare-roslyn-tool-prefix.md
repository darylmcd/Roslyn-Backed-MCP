- **Fixed:** the Roslyn-MCP connectivity gates in `skills/mcp-server-surface-test` — `SKILL.md` plus its two bundled tier prompts (`prompts/quick.md`, `prompts/full.md`) and the full tier's `prompts/phases/setup-and-analysis.md` — no longer match the server by tool-name *prefix*. Every gate on that skill's entry path now follows a **resolve-once-then-pin** rule: scan the tool surface for *every* tool whose name ends in `server_info`, identify the Roslyn one by its **response shape** (`connection.state` + `catalogVersion` + `surface.*`) rather than by its prefix, then **pin that tool's prefix** and resolve every later bare tool name in the skill and its phase sub-files under that one prefix only. The prefix is client-assigned from the registration path, so `mcp__roslyn__…`, `mcp__plugin_roslyn-mcp_roslyn__…`, a custom `.mcp.json` key, and a forked plugin name are all valid; the two common forms are named as examples only, not as an allowed list — a missing prefix literal is never itself grounds to halt. Pinning closes two misroutes that bare suffix matching left open: `server_info` is a common MCP tool name, so a non-Roslyn tool ending in that suffix would return no `connection.state` and trip the gate's own halt condition against a *healthy* install (now treated as "not this candidate — try the next one", not a halt); and unqualified later names such as `find_references` / `get_symbol_outline` collide with a co-registered Python/Jedi server, which would have attributed another server's results to Roslyn in findings this skill auto-files upstream as GitHub Issues. Halting is now reserved for the case where *no* `server_info` candidate returns a Roslyn-shaped response. Hard-stop semantics (`connection.state != ready`, `parityOk == false`) and the "no host-side `Read` / `Grep` / `Bash: dotnet build` fallback" prohibition are unchanged — the gate is prefix-agnostic and unambiguous, not weaker. Advances `shipped-skills-hardcode-bare-roslyn-tool-prefix`; the row **stays open**. Deferred: the same resolve-once-then-pin rewrite across the remaining ~18 shipped skills (including `skills/analyze/SKILL.md`, `skills/mcp-server-surface-test/README.md`, and the multisession-retro prompt file); a CI guard in `eng/verify-skills-are-generic.ps1` pinning the rule so a reintroduced prefix literal or a bare-suffix regression fails the build; and restructuring the canonical note itself (bullets instead of one dense paragraph, a trimmed `SKILL.md` frontmatter `description`, and de-duplicating the copy shared between `prompts/full.md` and its phase sub-file).
