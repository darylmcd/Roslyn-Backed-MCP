- **Fixed:** the Roslyn-MCP connectivity gates in `skills/mcp-server-surface-test` — `SKILL.md` plus its two bundled tier prompts (`prompts/quick.md`, `prompts/full.md`) and the full tier's `prompts/phases/setup-and-analysis.md` — no longer match the server by tool-name *prefix*. Every gate on that skill's entry path now resolves the server by **suffix** (any tool whose name ends in `server_info`) and halts only when *no* such tool exists. The prefix is client-assigned from the registration path, so `mcp__roslyn__…`, `mcp__plugin_roslyn-mcp_roslyn__…`, a custom `.mcp.json` key, and a forked plugin name are all valid; the two common forms are named as examples only, not as an allowed list. A consumer on any install shape can now clear the gate instead of aborting a legitimate run. Hard-stop semantics and the "no host-side `Read` / `Grep` / `Bash: dotnet build` fallback" prohibition are unchanged — the gate is prefix-agnostic, not weaker. Advances `shipped-skills-hardcode-bare-roslyn-tool-prefix`; the row **stays open**. Deferred: the same suffix-match rewrite across the remaining ~18 shipped skills (including `skills/analyze/SKILL.md`, `skills/mcp-server-surface-test/README.md`, and the multisession-retro prompt file), plus a prefix-agnostic guard assertion in `eng/verify-skills-are-generic.ps1` so a reintroduced prefix literal fails CI.
