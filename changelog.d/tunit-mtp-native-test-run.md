- **Fixed:** `test_run` can now execute TUnit test projects. TUnit is entirely built on Microsoft.Testing.Platform (MTP) and never registers with the classic VSTest adapter, so `--logger trx`/`--filter` were silently ignored for it. `test_run` now detects an MTP-only project and invokes it with the MTP-native argument shape (`--report-trx --results-directory <dir>`), producing the same TRX schema the existing result parser already understands. On the .NET 10 SDK the legacy VSTest-mode MTP bridge is hard-removed, so this requires the target repo's `global.json` to opt into the native mode (`"test": {"runner": "Microsoft.Testing.Platform"}`) — `test_run` throws an actionable error naming this when it's missing. A caller-supplied `--filter` is now translated to MTP's `--treenode-filter` syntax for the common tool-generated shape (one or more `FullyQualifiedName=`/`~` atoms OR'd together, naming tests within a single namespace+class); filters spanning multiple classes, using AND/grouping/negation, or naming a property other than `FullyQualifiedName` throw an actionable error instead of a silently-wrong translation — MTP's tree filter can only OR alternatives within one path segment, not across full test paths.
