- **Fixed:** `test_run` can now execute TUnit test projects. TUnit is entirely built on Microsoft.Testing.Platform (MTP) and never registers with the classic VSTest adapter, so `--logger trx`/`--filter` were silently ignored for it. `test_run` now detects an MTP-only project and invokes it with the MTP-native argument shape (`--report-trx --results-directory <dir>`), producing the same TRX schema the existing result parser already understands. On the .NET 10 SDK the legacy VSTest-mode MTP bridge is hard-removed, so this requires the target repo's `global.json` to opt into the native mode (`"test": {"runner": "Microsoft.Testing.Platform"}`) — `test_run` throws an actionable error naming this when it's missing. A caller-supplied `--filter` is translated to MTP's `--treenode-filter` syntax; using AND/grouping/negation, or naming a property other than `FullyQualifiedName`, throws an actionable error instead of a silently-wrong translation. OR-ing alternatives within one path segment is valid MTP grammar (confirmed correct by the MTP maintainer's own reflection probe), but a live production project reproduced it silently matching zero tests — the cause was an open bug in TUnit's own client-side pre-filter (thomhurst/TUnit#6026, not an MTP defect) discarding every test descriptor before MTP's real filter ran, fixed in `TUnit.Engine` 1.46.0. `test_run` now reads the target project's actual restored `TUnit.Engine` version from `project.assets.json` and only emits the OR shape when it's known to be at or above that fix; otherwise it throws, naming the resolved version (or that none could be determined) and the required upgrade.
