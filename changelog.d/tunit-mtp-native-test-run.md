- **Fixed:** `test_run` can now execute TUnit test projects. TUnit is entirely built on Microsoft.Testing.Platform (MTP) and never registers with the classic VSTest adapter, so `--logger trx`/`--filter` were silently ignored for it. `test_run` now detects an MTP-only project and invokes it with the MTP-native argument shape (`--report-trx --results-directory <dir>`), producing the same TRX schema the existing result parser already understands. On the .NET 10 SDK the legacy VSTest-mode MTP bridge is hard-removed, so this requires the target repo's `global.json` to opt into the native mode (`"test": {"runner": "Microsoft.Testing.Platform"}`) — `test_run` throws an actionable error naming this when it's missing. A caller-supplied `--filter` naming exactly one test is translated to MTP's `--treenode-filter` syntax; a filter naming more than one test (via `|`), using AND/grouping/negation, or naming a property other than `FullyQualifiedName` throws an actionable error instead of a silently-wrong translation. OR-ing alternatives within one path segment is valid MTP grammar (confirmed correct by the MTP maintainer's own reflection probe), but a live production project reproduced it silently matching zero tests — the cause is an open, unresolved bug in TUnit's own client-side pre-filter (thomhurst/TUnit#6026, not an MTP defect), which discards every test descriptor before MTP's real filter runs whenever a parenthesized segment lacks a literal `*`/`?`. No version check makes that shape safe to emit, so it's rejected outright.
