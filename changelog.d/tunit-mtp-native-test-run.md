- **Fixed:** `test_run` can now execute TUnit test projects. TUnit is entirely built on Microsoft.Testing.Platform (MTP) and never registers with the classic VSTest adapter, so `--logger trx`/`--filter` were silently ignored for it. `test_run` now detects an MTP-only project and invokes it with the MTP-native argument shape (`--report-trx --results-directory <dir>`), producing the same TRX schema the existing result parser already understands. On the .NET 10 SDK the legacy VSTest-mode MTP bridge is hard-removed, so this requires the target repo's `global.json` to opt into the native mode (`"test": {"runner": "Microsoft.Testing.Platform"}`) — `test_run` throws an actionable error naming this when it's missing. A caller-supplied `--filter` naming exactly one test is translated to MTP's `--treenode-filter` syntax; a filter naming more than one test (via `|`), using AND/grouping/negation, or naming a property other than `FullyQualifiedName` throws an actionable error instead of a silently-wrong translation. OR-ing alternatives within one path segment is valid MTP grammar and was verified to work on one MTP version, but a live production project on a different, currently-shipping MTP version (2.2.3) was found to silently match zero tests for that exact shape — a risk too high to translate into.
